카카오워크 2.0 근태관리 전면 개편

한눈에 보기

카카오워크는 카카오톡의 익숙함을 바탕으로 만든 협업 플랫폼입니다. 하지만 1.0에서는 타사 워크 플랫폼과 다른 점이 잘 보이지 않았고, 제품마다 경험이 달라 카카오워크만의 가치도 선명하게 드러나지 않았습니다. 회사는 MAU 5만 규모의 1.0을 근태관리·설문·할일관리 등 워크 엔진 전반을 고도화한 2.0으로 바꾸기로 했고, 저는 그중 사용 빈도와 VOC가 가장 높았던 근태관리를 맡았습니다.

기존 근태관리는 고정근무제를 기준으로 만든 초기 MVP였습니다. 출시 초기에는 기본 운영 도구로 충분했지만, 조직의 근무 방식이 바뀌면서 구조적인 한계가 보이기 시작했습니다.

유연근무제, 자율 선택 근무제, 원격근무, 해외 리모트 근무, 시간선택제, 하이브리드 워크 2.0처럼 근무 형태는 다양해졌습니다. 하지만 제품은 여전히 정해진 시간과 장소에서 일하는 상황을 기준으로 동작했습니다. 시스템이 흡수하지 못한 복잡함은 구성원과 관리자가 직접 처리해야 했습니다.

구성원은 비슷한 근무 정보를 매일 다시 입력했고, 근무 현황과 남은 휴가를 확인하려면 여러 정보를 직접 해석해야 했습니다. 관리자는 새 근무 제도와 예외를 시스템 밖에서 수기로 처리했습니다.

그래서 저는 이 프로젝트를 단순한 입력 UI 개선이 아니라, 복잡한 근무 제도를 시스템이 먼저 이해하고 처리하는 경험으로 정의했습니다.

리드 디자이너로서 사용자를 조사하고, 문제를 정의하고, 정보 구조와 인터랙션을 다시 설계했습니다. 와이어프레임과 하이파이 목업을 만들고 PM·개발·QA와 함께 실제 운영에 맞게 제품을 다듬었습니다.

문제

구성원의 문제

구성원은 근태관리에서 내 근무 현황을 빠르게 확인하고, 필요할 때 근무를 입력하거나 수정하고 싶어 했습니다. 하지만 기존 제품은 이 흐름을 한 번에 이어주지 못했습니다.

1. 월 근무 현황, 남은 근무시간, 남은 휴가를 확인하려면 여러 화면을 오가야 했습니다.
2. 시간을 드롭다운으로 하나씩 골라야 해서 입력이 오래 걸렸습니다.
3. 같은 근무 패턴도 매일 다시 입력해야 했습니다.
4. 휴일이나 입력할 수 있는 시간을 미리 알기 어려워 여러 번 다시 시도해야 했습니다.

관리자의 문제

관리자는 제도가 바뀌고 예외가 늘어날수록 제품 밖에서 더 많은 일을 처리했습니다.

1. 새 유연근무 제도를 관리자 화면과 운영 흐름에 바로 담기 어려웠습니다.
2. 자동으로 처리해야 할 운영 업무를 수기로 관리했습니다.
3. 시스템이 처리하지 못한 예외를 메신저 같은 별도 채널에서 반복해서 해결했습니다.

정리하면, 화면 몇 개를 고쳐서 풀 문제가 아니었습니다.

근태관리 시스템이 실제 근무 방식에 맞춰 다시 설계되어야 했습니다.

리서치 & 인사이트

설계하기 전에 기존 카카오워크 1.0이 어디에서 흐름을 끊는지 확인했습니다. 구성원과 관리자를 대상으로 설문과 심층 인터뷰를 진행해 실제 운영과 제품 경험 사이의 차이를 찾았습니다.

설문 주요 결과

개선된 근태관리에 기대한 점:

- 근태를 더 쉽게 입력하기 68.7%
- 새 근무제도를 자동으로 적용하기 71.7%

기존 서비스 이용 경험:

- 불편을 느꼈다 69.1%
- 주요 불편 요소: 근태 입력이 어려움 > 정보 확인이 어려움 > 휴가 신청이 어려움

인터뷰 핵심 인사이트

1) 사용자는 더 많은 입력 단계보다 빠른 확인을 원했습니다

사용자는 복잡한 제도를 공부하려고 근태관리에 들어오지 않습니다. 알고 싶은 것은 네 가지였습니다.

- 오늘 내 근무가 어떻게 기록되어 있는지
- 이번 달에 얼마나 일했는지
- 휴가가 얼마나 남았는지
- 지금 더 입력할 것이 있는지

필요한 것은 바로 확인하고 빠르게 끝내는 경험이었습니다.

2) 관리자의 진짜 문제는 운영이었습니다

관리자를 힘들게 한 것은 제도의 복잡함 자체가 아니라, 제품이 제도를 처리하지 못해 생기는 반복적인 수기 작업이었습니다. 유연근무 제도와 예외 규칙이 관리자 화면과 운영 흐름에 자연스럽게 이어져야 했습니다.

결론

- 사용자는 쉽게 입력하고 빠르게 확인하고 싶어 합니다.
- 관리자는 수기 작업을 줄이고 자동으로 운영되는 시스템을 원합니다.
- 둘 다에게 필요한 것은 기능 추가보다, 복잡한 제도를 대신 처리해 주는 제품 구조였습니다.

좋은 UX는 사용자에게 규칙을 외우게 하지 않습니다. 시스템이 먼저 이해하고 처리합니다.

설계 방향
학습 없이 바로 쓰는 근태 경험

리서치 인사이트를 바탕으로 세 가지 설계 방향을 정했습니다.

1) 달라진 근무제도를 담는 구조

고정근무제 중심 구조를 다양한 근무 제도를 수용하는 구조로 다시 설계합니다.

2) 빠르게 끝나는 입력 경험

제도를 몰라도 보자마자 쓸 수 있는 입력 흐름을 만듭니다.

3) 제품 안에서 이어지는 운영

시스템 밖에서 처리하던 반복 작업과 예외 대응을 제품 안으로 가져옵니다.

이번 개편의 목표는 달라진 근무 제도가 구성원과 관리자 모두에게 자연스럽게 작동하는 경험을 만드는 것이었습니다.

Design Principles

원칙 1. 중요한 정보부터 보여줍니다

기존 첫 화면은 정보와 기능이 흩어져 있어 어디서 무엇을 해야 할지 판단하기 어려웠습니다. 사용자가 자주 확인하는 정보는 명확했습니다. 내 근무 현황, 남은 휴가, 오늘 필요한 액션입니다. 홈 화면은 기능을 나열하는 대신 이 세 가지가 가장 먼저 보이도록 정보 구조를 다시 정리했습니다.

원칙 2. 입력은 설명 없이 끝납니다

기존에는 드롭다운으로 시간을 일일이 맞춰야 했고, 허용 범위를 벗어나면 뒤늦게 에러가 났습니다. 근태 입력은 보자마자 할 수 있어야 합니다. 그래서 시간 입력을 타임라인 위에서 드래그와 클릭으로 조작하는 방식으로 바꾸고, 입력할 수 있는 날짜와 시간을 먼저 보여줬습니다.

원칙 3. 반복은 시스템이 맡습니다

구성원 대부분은 일정한 패턴으로 일합니다. 그런데 기존 시스템은 같은 패턴을 매일 새로 입력하게 했습니다. 자주 쓰는 근무 패턴을 템플릿으로 저장하면 기본값이 자동으로 적용되도록 설계해, 사용자는 예외가 있는 날만 수정하면 되도록 했습니다.

결과

무엇을 만들었나

상태 중심 홈 화면, 타임라인 근무 입력, 근무 템플릿, 팀 현황, 프로필 상태 자동 연동까지 구성원과 관리자 화면 전반을 개편했습니다. 기존 시스템이 사용자에게 넘기던 유연근무 제도의 복잡함을 제품이 흡수하도록 만들었습니다.

측정한 임팩트

개편 후 카카오워크 내부 설문 시스템으로 CBT를 진행했고 만족도 82.85%를 확인했습니다. 참여자들은 어려웠던 UI가 이해하기 쉬워져 도움 없이 근태를 관리할 수 있게 됐다고 평가했습니다. 업무 동선을 다시 짜 반복 업무의 클릭 수를 3–5회 줄였고, 디자인 시스템 2.0으로 디자인 부채를 줄여 제품 개발 속도를 약 40% 높였습니다.

어떻게 검증했나

격주 사용성 테스트로 사용자 피드백을 제품 의사결정에 담았습니다. HR 관리자와 구성원을 대상으로 필드 리서치를 진행해 제도 운영의 페인 포인트를 찾고, 이를 디자인 방향과 로드맵에 연결했습니다. CBT에서 받은 불만 피드백 15.13%는 대부분 ‘기존 UI에 익숙해 새 화면을 배우는 시간이 든다’는 내용이었고, 이를 2차 개선 백로그로 정리해 다음 업데이트를 계획했습니다.

무엇을 배웠나

가장 큰 개선은 일을 없애는 데서 나왔습니다. 시스템이 해석·반복·판단을 대신하면 구성원과 관리자 모두 시간을 돌려받습니다. 근태 정책의 복잡함은 화면 몇 개보다 시스템 차원에서 풀어야 하는 문제였고, 그 관점이 제품을 단순하게 만들었습니다.

주요 설계

1. 근무 상태를 계산 없이 확인합니다

근태관리 홈의 목표는 사용자가 지금 내 상태를 바로 이해하게 하는 것입니다. 기존 화면에서는 사용자가 근무한 시간과 앞으로 근무해야 하는 시간을 직접 계산해야 했습니다. 개편한 메인 화면에는 월 근무 현황과 남은 휴가를 함께 배치했습니다. 사용자는 소정 근무 시간, 총 근무 시간, 실 근무 시간, 유급 휴가를 한눈에 확인할 수 있습니다. 연차·가족돌봄·건강검진·난임휴가처럼 헷갈리기 쉬운 휴가별 잔여 시간도 쉬운 문구로 풀어 숫자를 해석하는 부담을 줄였습니다.

2. 근무 입력은 ‘설정’보다 ‘조정’에 가깝습니다

실제 사용자의 하루는 대부분 기본 근무 패턴에서 조금씩만 달라집니다. 그래서 근무 입력을 매번 처음부터 설정하게 하지 않고, 기본값을 필요할 때만 고치는 방식으로 바꿨습니다. 24시간 타임라인 위에서 근무 블록을 드래그하거나 클릭하면 기본 근무, 재택, 추가 근무를 바로 수정할 수 있습니다. 텍스트 입력 중심의 설정을 시각적인 조정으로 바꾸자, 하루 근무 구성을 훨씬 쉽게 확인하고 고칠 수 있었습니다.

3. 실수한 뒤가 아니라, 실수하기 전에 알려줍니다

회사마다 제도와 규칙이 달라 사용자가 모든 조건을 기억하기는 어렵습니다. 그래서 휴일이나 제한 시간이 있는 날짜에는 선택할 수 있는 액션을 먼저 보여줍니다. 입력이 끝난 뒤 에러를 띄우기보다, 사용자가 가능한 선택지를 먼저 보게 하는 구조입니다. 규칙을 외우고 판단하는 일은 시스템이 대신합니다.

4. 반복 입력은 템플릿이 대신합니다

매일 같은 근무 시간을 입력하는 일은 리서치에서 가장 자주 나온 불편이었습니다. 팀과 근무 방식에 맞는 템플릿을 저장해 두면 매일 기본 근무값이 자동으로 적용됩니다. 출근 시간이 달라지거나 재택으로 바뀌는 날에는 해당 부분만 수정하면 됩니다. 반복되던 행동을 제품의 기본 동작으로 흡수해, 사용자가 신경 쓸 일을 줄였습니다.

5. 팀 근무 현황에서 협업 가능 여부를 바로 확인합니다

유연근무 환경에서 협업은 동료의 상태를 아는 데서 시작합니다. 팀 근무 현황 화면은 구성원별 근무 시간을 타임라인으로 보여주고, 현재 상태를 출근·재택·휴가·근무 대기로 구분합니다. 화면의 기준은 ‘지금 이 사람과 협업할 수 있는가’를 바로 확인할 수 있는가였습니다. 상세한 운영 정보보다 상태 확인에 집중해, 하이브리드 환경에서 팀의 시간을 공유하는 협업 도구로 만들었습니다.

6. 근태 입력과 상태 공유를 한 번에 끝냅니다

기존에는 근태를 입력한 뒤 카카오워크 프로필 상태도 따로 바꿔야 했습니다. 같은 정보를 두 번 입력하지 않도록, 근태관리에 입력한 근무 정보가 프로필 상태에 자동으로 이어지게 설계했습니다. 따로 체크인하지 않아도 근무 중·휴가·자리비움 상태가 팀에 공유됩니다. 자동 연동이 불안하게 느껴지지 않도록 언제 어떤 정보가 공유되는지 명확히 안내했습니다. 이 지점에서 UX 라이팅은 자동화에 대한 불안을 줄이는 신뢰 장치가 됐습니다.

7. 연차는 시스템이 자동으로 관리합니다

관리자에게 가장 큰 부담은 연차였습니다. 입사일 기준인지 회계일 기준인지, 해마다 쌓이는 가산 연차와 소멸 규칙까지 근로기준법에 맞춰 따져야 했고, 시스템이 처리하지 못한 부분은 수기로 관리했습니다. 그래서 연차 발생 기준과 자동 소멸 규칙을 한 번만 설정하면 이후 부여·소멸·잔여 현황을 시스템이 자동으로 계산하도록 설계했습니다. 어려운 노무 정보는 설정에 필요한 항목만 남기고, 통일된 컴포넌트와 쉬운 캡션으로 읽기 쉽게 만들었습니다. 관리자가 설정한 제도는 구성원 화면에 바로 보여줘, 구성원도 우리 회사 제도를 쉽게 이해하고 쓸 수 있습니다.

8. 디자인 시스템 2.0으로 제품 경험을 하나로 맞췄습니다

개편을 진행하며 더 큰 문제도 보였습니다. 버티컬마다 디자인 시스템이 달라 카카오워크가 하나의 제품처럼 느껴지지 않았습니다. 그래서 세 가지 원칙으로 디자인 시스템 2.0을 함께 구축했습니다. Familiarity — 새 디자인 언어를 도입하기보다 기존 제품에서 쓰던 패턴을 찾아 컴포넌트로 정의했습니다. Consistency — 모든 제품군이 같은 디자인 언어를 쓰게 해, 제품을 오갈 때 이질감이 줄었습니다. Efficiency — 버티컬마다 따로 쓰던 시스템을 통일해 개발 리소스가 흩어지는 문제를 줄였습니다. 이 시스템이 개발 속도를 약 40% 높인 기반입니다.
