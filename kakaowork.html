카카오워크 2.0 근태관리 전면 개편

복잡한 근무 제도를 근무자가 외우지 않아도 되는 근태 경험

OVERVIEW

카카오워크 2.0의 근태관리 서비스를 전면 개편한 프로젝트입니다. 기존 1.0 근태관리는 고정근무제를 기준으로 빠르게 출시된 MVP였지만, 유연근무제·자율 선택 근무제·원격근무·해외 리모트 근무·하이브리드 워크처럼 근무 방식이 다양해지면서 근무자와 관리자 모두에게 복잡함이 전가되고 있었습니다.

이 프로젝트의 목표는 근태 입력 화면을 조금 더 쉽게 만드는 것이 아니었습니다. 달라진 근무 제도와 예외 규칙을 시스템이 먼저 이해하고, 근무자는 자신의 상태와 다음 행동만 빠르게 확인할 수 있는 근태 경험을 만드는 것이었습니다.

카카오워크는 카카오톡의 익숙함을 바탕으로 만든 협업 플랫폼입니다. 1.0 단계에서는 메신저 중심의 기본 업무 기능을 빠르게 제공했지만, 근태관리·설문·할일관리처럼 워크 엔진이 확장될수록 제품마다 경험이 달라지고 카카오워크만의 일관된 가치가 흐려지는 문제가 있었습니다.

그중 근태관리는 사용 빈도와 VOC가 가장 높은 영역이었습니다. 기존 근태관리 MVP는 정해진 시간과 장소에서 일하는 고정근무제를 기준으로 설계되어 있었습니다. 그러나 실제 조직의 근무 방식은 이미 바뀌고 있었습니다. 코어타임 없이 자율적으로 근무하거나, 장소를 선택하거나, 원격근무와 하이브리드 워크를 병행하는 회사가 늘었습니다.

제품이 이 복잡함을 흡수하지 못하자, 근무자는 매일 비슷한 근무 정보를 다시 입력해야 했고 관리자는 새 근무 제도와 예외를 시스템 밖에서 수기로 처리해야 했습니다.

문제는 근태를 입력하기 어려운 화면 하나가 아니라, 달라진 근무 제도를 근무자와 관리자가 직접 해석하고 처리해야 하는 구조였습니다.

그래서 저는 이 프로젝트를 단순한 UI 개선이 아니라, 근무 규칙은 시스템이 처리하고 근무자는 필요한 상태와 다음 행동만 이해하는 경험으로 재정의했습니다.

DIAGNOSIS

1. 근태관리 MVP는 바뀐 근무제도를 담지 못하고 있었습니다

기존 제품은 빠르게 근무를 등록하고 현황을 보는 데 초점을 둔 초기 MVP였습니다. 출시 초기에는 기본 운영 도구로 충분했지만, 유연근무제와 원격근무가 확산되면서 제품 구조가 실제 근무 방식을 따라가지 못했습니다.

시간선택제, 투명한 근무제, 자율 선택 근무제, 해외 리모트 근무, 하이브리드 워크 2.0처럼 제도는 늘어났지만 화면은 여전히 정해진 시간과 장소에서 일하는 상황을 기준으로 움직이고 있었습니다.

2. 근무자는 근무현황 확인과 근무입력 사이에서의 다른 UX 경험을 겪고 있었습니다

근무자는 근태관리에서 복잡한 제도를 배우고 싶어 하지 않았습니다. 업무 전에 정보 입력 및 정보 습득을 간편하게 하고 싶어 하는 경향이 강했습니다.

- 오늘 내 근무가 어떻게 기록되어 있는지
- 이번 달에 얼마나 일했는지
- 남은 휴가가 얼마나 있는지
- 지금 더 입력해야 할 것이 있는지

하지만 기존 제품은 근무현황을 확인하는 경험과 근무시간을 입력하는 경험이 서로 다르게 느껴졌습니다. 현황 화면에서는 월 근무시간과 남은 휴가를 직접 해석해야 했고, 입력 화면에서는 시간을 드롭다운으로 하나씩 골라야 했습니다. 입력 가능한 날짜와 시간이 미리 안내되지 않아 여러 번 다시 시도해야 하는 일도 생겼습니다.

3. 관리자는 근무제도와 예외를 시스템 밖에서 처리하고 있었습니다

관리자의 문제는 화면 사용성보다 운영에 가까웠습니다. 새로운 근무제도를 반영하거나 연차·대체휴무·보상휴가처럼 다양한 경우의 수를 관리하려면 시스템 밖에서 확인하고 수기로 처리해야 했습니다.

자동화되지 않은 요소가 많을수록 HR 운영자는 같은 일을 반복했고, 근무자에게 안내해야 할 내용도 늘어났습니다. 관리자는 제도를 설정하고, 근무자는 그 제도를 이해하고, 제품은 두 흐름을 자연스럽게 이어줘야 했습니다.

4. 카카오워크 제품군은 서로 다른 디자인 언어를 사용하고 있었습니다

근태관리만의 문제도 있었지만, 더 큰 문제는 카카오워크의 여러 워크 제품군이 서로 다른 디자인 언어를 사용하고 있다는 점이었습니다. 근무자는 제품을 오갈 때마다 다른 규칙을 다시 학습해야 했고, 개발 조직도 버티컬마다 따로 시스템을 유지해야 했습니다.

결론은 분명했습니다. 근태관리는 화면 몇 개를 고쳐서 해결할 수 있는 문제가 아니라, 근무제도·입력·운영·상태 공유가 하나의 시스템으로 연결되어야 하는 문제였습니다.

RESEARCH

카카오워크 2.0 근태관리 설계를 위해 기존 1.0 근무자와 관리자를 대상으로 설문과 심층 인터뷰를 진행했습니다. 목표는 근무자가 어디에서 막히는지, 관리자가 어떤 운영 부담을 제품 밖에서 처리하고 있는지 확인하는 것이었습니다.

설문에서 확인한 기대와 불편

- 더 쉬운 근태관리 등록 68.7%
- 새로운 근무제도 자동화 적용 71.7%
- 기존 근태관리 사용 경험에서 불편을 느꼈다 69.1%

주요 불편 요소는 근태 등록이 어려움, 정보 파악이 힘듦, 휴가 등록이 어려움 순으로 나타났습니다.

근무자는 규칙 학습보다 빠른 확인을 원했습니다.

근무자는 근태관리 안에서 복잡한 근무 제도를 공부하려고 하지 않습니다. 오늘 내 상태와 이번 달 누적 근무, 남은 휴가, 지금 필요한 액션을 빠르게 알고 싶어 했습니다.

관리자는 복잡한 제도보다 반복 운영이 더 힘들었습니다.

관리자는 제도 자체가 복잡한 것보다, 제품이 제도를 자동으로 처리하지 못해 생기는 반복 수기 작업을 더 큰 문제로 느꼈습니다. 새 근무 제도가 어디에 반영되고, 어떤 예외가 자동 처리되며, 근무자 화면에는 어떻게 보이는지가 중요했습니다.

근무자와 관리자에게 필요한 것은 기능 추가가 아니라 구조 변화였습니다.

근무자에게는 쉬운 입력과 빠른 확인이 필요했고, 관리자에게는 수기 작업 없이 운영되는 시스템이 필요했습니다. 좋은 근태 UX는 근무자에게 규칙을 외우게 하지 않습니다. 시스템이 먼저 이해하고 처리해야 합니다.

APPROACH
규칙은 시스템이 처리하고, 근무자는 필요한 행동만 확인합니다

리서치 결과를 바탕으로 세 가지 설계 방향을 정했습니다.

1. 달라진 근무제도를 담는 구조

고정근무제 중심 구조가 실제 근무 방식을 따라가지 못하고 있었습니다. 그래서 유연근무·원격근무·시간선택제·하이브리드 워크를 수용하는 정보 구조로 다시 설계했습니다.

2. 빠르게 끝나는 입력 경험

드롭다운과 반복 입력 때문에 근태 등록이 오래 걸렸습니다. 그래서 타임라인 조작, 기본값 적용, 입력 가능 상태 선노출을 기준으로 입력 흐름을 다시 만들었습니다.

3. 제품 안에서 이어지는 운영

관리자가 예외와 연차를 수기로 처리하고 있었습니다. 그래서 정책 설정, 자동 부여·소멸, 근무자 화면 즉시 반영이 하나의 흐름으로 이어지도록 설계했습니다.

이번 개편의 핵심은 “근태를 더 많이 입력하게 하는 것”이 아니었습니다. 근무자가 신경 써야 하는 계산, 반복, 판단을 제품이 대신 처리하게 만드는 것이었습니다.

Design Principles

1. 중요한 정보부터 보여줍니다

기존 첫 화면은 정보와 기능이 흩어져 있어 근무자가 어디에서 무엇을 해야 하는지 판단하기 어려웠습니다. 근무자가 자주 확인하는 정보는 명확했습니다. 내 근무 현황, 남은 휴가, 오늘 필요한 액션입니다. 그래서 홈 화면은 기능을 나열하는 대신 이 세 가지가 가장 먼저 보이도록 정보 구조를 다시 정리했습니다.

2. 입력은 설명 없이 끝나야 합니다

기존에는 시간을 드롭다운으로 하나씩 맞춰야 했고, 허용 범위를 벗어나면 입력이 끝난 뒤에야 에러가 나타났습니다. 근태 입력은 근무자가 제도를 해석하지 않아도 보자마자 할 수 있어야 했습니다. 그래서 근무 시간을 24시간 타임라인 위에서 드래그와 클릭으로 조정하게 만들고, 입력할 수 없는 날짜와 시간은 먼저 보여주도록 했습니다.

3. 반복은 시스템이 맡습니다

근무자 대부분은 일정한 패턴으로 일합니다. 하지만 기존 시스템은 같은 패턴을 매일 새로 입력하게 했습니다. 자주 쓰는 근무 패턴을 템플릿으로 저장하면 기본값이 자동으로 적용되도록 설계했습니다. 근무자는 매일 다시 입력하는 대신, 예외가 있는 날만 수정하면 됩니다.

VALIDATION / OUTCOME

VALIDATION

개편 후 카카오워크 내부 설문 시스템으로 CBT를 진행했습니다. 목표는 새로운 근태관리 구조가 실제 근무자와 관리자에게 이해 가능한지, 도움 없이 근태를 관리할 수 있는지 확인하는 것이었습니다.

CBT 결과

- 만족도 82.85%
- 매우 만족 43%
- 만족 39.83%
- 조금 불만 8.95%
- 불만 6.18%
- 불만 피드백 합계 15.13%

근무자와 관리자는 기존의 어려웠던 UI가 이해하기 쉬운 UI로 바뀌어, 도움 없이 근태관리를 할 수 있게 됐다고 평가했습니다.

OUTCOME

근무자와 관리자 화면 전반을 함께 개편했습니다. 상태 중심 홈 화면, 타임라인 근무 입력, 근무 템플릿, 팀 현황, 프로필 상태 자동 연동, 연차 자동 부여·소멸, 관리자 설정 화면, 디자인 시스템 2.0까지 연결했습니다.

프로젝트 기간 동안 전달한 산출물은 근태관리 2.0 문제 정의, 리서치 인사이트, 근무자용 근태 홈, 관리자용 정책 설정, 프로필 상태 자동 연동 플로우, CBT 결과 분석, 디자인 시스템 2.0 원칙과 공통 컴포넌트였습니다.

상태 확인 → 쉬운 조정 → 반복 자동화 → 운영 연결

근무자는 자신의 근무 상태와 남은 휴가를 빠르게 확인하고, 근무시간은 타임라인 위에서 조정하며, 반복되는 근무 패턴은 템플릿으로 자동 적용됩니다. 관리자는 복잡한 연차와 근무 정책을 한 번 설정하고, 시스템은 그 규칙을 근무자 화면과 운영 흐름에 이어줍니다.

LEARNING 01

B2B SaaS의 UX는 화면보다 운영 구조를 정리하는 일에 가까웠습니다. 근태관리의 복잡함은 UI 요소가 많아서 생긴 문제가 아니라, 실제 회사 제도와 예외가 제품 안에서 처리되지 못해 생긴 문제였습니다. 그래서 화면을 단순하게 만드는 것보다 먼저, 어떤 규칙을 시스템이 맡고 어떤 판단만 사용자에게 남길지 정하는 것이 중요했습니다.

LEARNING 02

가장 큰 개선은 기능을 더하는 것이 아니라 일을 없애는 데서 나왔습니다. 반복 입력, 수기 확인, 상태 공유, 연차 계산처럼 근무자와 관리자가 매번 처리하던 일을 시스템의 기본 동작으로 흡수했을 때 경험이 단순해졌습니다. 좋은 자동화는 사람을 대체하는 것이 아니라, 근무자와 관리자가 신경 쓰지 않아도 되는 일을 줄여줍니다.

LEARNING 03

디자인 시스템은 제품 확장을 위한 운영 장치입니다. 카카오워크처럼 여러 워크 엔진이 함께 커지는 서비스에서는 각 기능이 따로 잘 만들어지는 것만으로는 부족합니다. 같은 컴포넌트, 같은 언어, 같은 상호작용 규칙으로 연결되어야 근무자는 하나의 제품으로 인식하고, 팀은 더 빠르게 만들 수 있습니다.

DESIGN DECISIONS
상태 확인 → 쉬운 조정 → 반복 자동화 → 운영 연결

01. 근무 상태를 계산 없이 확인하게 했습니다

근태관리 홈의 목표는 근무자가 지금 내 상태를 바로 이해하게 하는 것입니다. 기존 화면에서는 근무자가 근무한 시간과 앞으로 근무해야 하는 시간을 직접 계산해야 했습니다.

개편한 메인 화면에는 월 근무 현황과 남은 휴가를 함께 배치했습니다. 소정 근무 시간, 총 근무 시간, 실 근무 시간, 유급 휴가를 한눈에 볼 수 있게 하고, “136시간 남았어요”처럼 해석이 필요한 숫자를 쉬운 문장으로 바꿨습니다.

연차·가족돌봄·건강검진·난임휴가처럼 헷갈리기 쉬운 휴가별 잔여 시간도 쉬운 문구로 풀어 숫자를 해석하는 부담을 줄였습니다.

02. 근무 입력을 설정이 아니라 조정에 가깝게 만들었습니다

실제 사용자의 하루는 대부분 기본 근무 패턴에서 조금씩만 달라집니다. 그래서 근무 입력을 매번 처음부터 설정하게 하지 않고, 기본값을 필요할 때만 고치는 방식으로 바꿨습니다.

24시간 타임라인 위에서 근무 블록을 드래그하거나 클릭하면 기본 근무, 재택, 추가 근무를 바로 수정할 수 있습니다. 텍스트 입력 중심의 설정을 시각적인 조정으로 바꾸자, 하루 근무 구성을 훨씬 쉽게 확인하고 고칠 수 있었습니다.

03. 실수한 뒤가 아니라, 실수하기 전에 알려줬습니다

회사마다 제도와 규칙이 다르기 때문에 근무자가 모든 조건을 기억하기는 어렵습니다. 그래서 휴일이나 제한 시간이 있는 날짜에는 선택할 수 있는 액션을 먼저 보여줬습니다.

입력이 끝난 뒤 에러를 띄우기보다, 근무자가 가능한 선택지를 먼저 보게 하는 구조입니다. 규칙을 외우고 판단하는 일은 시스템이 대신합니다.

04. 반복 입력은 템플릿이 대신하게 했습니다

매일 같은 근무 시간을 입력하는 일은 리서치에서 가장 자주 나온 불편이었습니다. 팀과 근무 방식에 맞는 템플릿을 저장해 두면 매일 기본 근무값이 자동으로 적용됩니다.

출근 시간이 달라지거나 재택으로 바뀌는 날에는 해당 부분만 수정하면 됩니다. 반복되던 행동을 제품의 기본 동작으로 흡수해, 근무자가 신경 쓸 일을 줄였습니다.

05. 팀 근무 현황에서 협업 가능 여부를 바로 확인하게 했습니다

유연근무 환경에서 협업은 동료의 상태를 아는 데서 시작합니다. 기존 화면은 정보가 많고 복잡해 팀원의 출근시간을 한눈에 파악하기 어려웠습니다.

팀 근무 현황 화면은 근무자별 근무 시간을 타임라인으로 보여주고, 현재 상태를 출근·재택·휴가·근무 대기로 구분했습니다. 화면의 기준은 “지금 이 사람과 협업할 수 있는가”를 바로 확인할 수 있는가였습니다.

06. 근태 입력과 프로필 상태 공유를 한 번에 끝냈습니다

기존에는 근태를 입력한 뒤 카카오워크 프로필 상태도 따로 바꿔야 했습니다. 같은 정보를 두 번 입력하지 않도록, 근태관리에 입력한 근무 정보가 프로필 상태에 자동으로 이어지게 설계했습니다.

따로 체크인하지 않아도 근무 중·휴가·자리비움 상태가 팀에 공유됩니다. 자동 연동이 불안하게 느껴지지 않도록 언제 어떤 정보가 공유되는지 명확히 안내했습니다. 이 지점에서 UX 라이팅은 자동화에 대한 불안을 줄이는 신뢰 장치가 됐습니다.

07. 연차 관리는 관리자가 한 번 설정하면 시스템이 자동으로 처리하게 했습니다

관리자에게 가장 큰 부담은 연차였습니다. 입사일 기준인지 회계일 기준인지, 매년 발생하는 가산 연차와 소멸 규칙까지 근로기준법에 맞춰 따져야 했고, 시스템이 처리하지 못한 부분은 수기로 관리했습니다.

그래서 연차 발생 기준과 자동 소멸 규칙을 한 번만 설정하면 이후 부여·소멸·잔여 현황을 시스템이 자동으로 계산하도록 설계했습니다. 어려운 노무 정보는 설정에 필요한 항목만 남기고, 통일된 컴포넌트와 쉬운 캡션으로 읽기 쉽게 만들었습니다.

관리자가 설정한 제도는 근무자 화면에 바로 반영됩니다. 근무자도 우리 회사 제도를 따로 물어보지 않고 제품 안에서 이해하고 사용할 수 있습니다.

08. 디자인 시스템 2.0으로 제품 경험을 하나로 맞췄습니다

개편을 진행하며 더 큰 문제도 함께 보였습니다. 카카오워크 안의 다양한 기능들이 워크 플랫폼이라는 공통 성격을 갖고 있음에도, 디자인 정렬이 맞지 않아 제품군마다 다른 서비스처럼 보였습니다.

그래서 디자인 시스템 2.0을 세 가지 원칙으로 정리했습니다.

Familiarity — 완전히 새로운 언어를 만들기보다 기존 제품에서 쓰이던 익숙한 패턴을 컴포넌트로 정의합니다.
Consistency — 모든 제품군이 같은 디자인 언어를 사용해 근무자가 제품을 오갈 때 이질감을 느끼지 않게 합니다.
Efficiency — 버티컬마다 따로 쓰던 시스템을 통합해 개발 리소스가 흩어지는 문제를 줄입니다.

디자인 시스템은 화면을 예쁘게 맞추는 작업이 아니라, 제품이 확장될 때 같은 속도와 품질로 움직이게 하는 기반이었습니다.
